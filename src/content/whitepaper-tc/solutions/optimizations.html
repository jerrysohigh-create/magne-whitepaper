M Hash 優化方案

下列保留早期工程方案，不據此宣稱已部署或已有實測加速。發布成果須附對應程式改動、配置及可重現基準測試。

執行層

方案須驗證事項
共享中間狀態快取（L1.5）快取所有權、記憶體上限、失效及重組處理。
Diff Layer 深度 128 → 32同一工作負載下的讀取放大、誤判及記憶體／磁碟取捨。
originStorage 預取共享執行緒安全、命中率及狀態讀取一致性。
重用區塊執行結果酬載身份、分叉／版本相容性及必要重驗；Engine API 版本須與客戶端匹配。

批次發布

非同步批次提交可能減少發布間等待，但須追蹤 L1 納入、替換與重組恢復。舊稿「15 次確認／45 秒」不是已確認的現行設定；批次提交延遲與結算最終確定須分開測量。

驗收依據

每項採用的改動應列出倉庫與 commit、客戶端版本、配置、測試負載、前後對照及故障情境結果；此前維持方案狀態，不作吞吐量保證。
