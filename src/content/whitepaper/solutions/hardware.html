Hardware: security and computation

MAG1 brings device computation, protected key operations and network access into one product. These roles are distinct; supported features depend on the device, software and application configuration.

Three security layers

The official security description references UTEE (CC EAL2+), HyperSeed N60 (CC EAL6+) and HyperSeed 72B (CC EAL6+). These are component or evaluated-scope references, not an EAL rating for the whole phone.

HyperSeed N60

The secure-element path is designed to keep protected keys inside the hardware and return signatures or authorised results. Actual use depends on the wallet, access rules and user authorisation; not every application transaction automatically follows this path.

HyperSeed 72B

The separate NFC recovery design protects recovery material. Recovery access and backup handling must follow the configured procedure. Retention and endurance depend on the applicable component specification and operating conditions.

UTEE

A trusted execution environment separates designated sensitive operations from ordinary applications. It is a different protection boundary from the secure element.

System security

Permission checks, trusted execution, secure signing, software updates and operational testing work together. These controls reduce exposure; they do not promise immunity from malware, malicious approvals or implementation flaws.

On-device AI

Local inference can reduce dependence on cloud processing for supported workloads. Translation, assistance and detection use cases require their own model, application and device testing; running locally does not by itself establish complete privacy.

Network participation

Wallets and applications can access supported networks. Proposed GEN1 rewards concern eligible device tasks and availability, not automatic L1 validator status or L2 consensus rights.
