M Hash optimisation proposals

The items below preserve the earlier engineering proposals. Their inclusion does not establish deployment or a measured speed-up. A release claim requires the relevant code change, configuration and reproducible benchmark.

Batch publication

Asynchronous batch submission may reduce waiting between publications, but must track L1 inclusion, replacement and reorganisation recovery. The old “15 confirmations / 45 seconds” example is not a confirmed current setting. Batch submission latency and settlement finality must be measured separately.

Acceptance evidence

For each adopted change, publish the repository and commit, client version, configuration, test workload, before/after measurements and failure-case results. Until then these remain proposals, not published throughput guarantees.
