Glossary

Terms used in this draft

MHA / Magic Hash

Current BSC token; total allocation 10 billion. Future MAGNE network uses are proposals until enabled.

mBGT

Design reference for reward coordination and protocol voting; retention, issuance and its relation to MHA remain to be confirmed.

MagneKit

Project framework name in earlier material. Its client implementation, consensus engine and release version require technical confirmation.

CometBFT

A Byzantine fault-tolerant consensus engine. Mentioning it in a design does not establish that a MAGNE network runs it.

Consensus

Rules by which nodes agree on accepted blocks and state. Separate from reward budgeting and device-task verification.

PoW

Proof of Work: a consensus family using computational competition. Not a synonym for any rewarded computation.

PoL

Proof of Liquidity: a proposed liquidity-participation and reward-allocation mechanism in this design.

PoAI / GEN1

Device-work design and first-generation device reward programme. Eligibility, budget and release are specified in Tokenomics.

Validator / sequencer

Validator responsibilities follow L1 consensus; a sequencer orders L2 transactions. Neither role is automatically granted by owning a phone.

Block / block time

A block records transactions and state commitments. Block time must identify the chain and observation period.

Execution client / Engine API

An execution client processes state transitions. Engine API connects execution with the applicable consensus or rollup component; supported versions depend on the release.

Finality / withdrawal period

Finality describes when a chain accepts a state as final under its security model. A bridge withdrawal may have a separate challenge or processing period.

Single-slot finality

Finalisation within a slot under a specific protocol. This glossary does not assert that MAGNE implements it.

Staking / delegation

Staking subjects assets to specific protocol rules. Delegation can assign voting or validation weight; it is not necessarily an asset transfer and must identify the governing contract.

Governance

Proposal, review, voting and execution of changes under stated authority. The voting asset and deployed governance status must be explicit.

DEX / MagneSwap

A decentralised exchange supports swaps through contracts. MagneSwap remains a planned project application in this draft.

Liquidity / pool / LP

Liquidity is executable market depth. Pools hold assets under contract rules; liquidity providers bear the applicable price and contract risks.

Reward vault

A contract arrangement for eligible assets and funded incentives. Admission, rates and claim rules depend on its deployed version.

Released / disbursed / claimable

Reserve release makes budget available under its schedule. Disbursement uses an approved budget. Claimable amounts have met the recipient release conditions. These are not interchangeable balances.

Testnet / mainnet

Testnet assets and records serve testing. Production/mainnet status requires a separate launch; testnet availability does not establish production settlement.
