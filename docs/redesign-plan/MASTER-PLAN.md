# MAGNE.AI 文档站与白皮书版本体系规划

日期：2026-09-29。状态：方案草案，待视觉方案选择及内容负责人确认。此次只创建规划和现场截图，不修改任何站点页面、不部署。

## 1. 目标与三个站点的分工

让读者找到可信的当前资料，让团队能够持续更新并解释变化。视觉统一到品牌家族，信息用途保持清晰。

| 站点 | 推荐角色 | 首要任务 | 内容归属 |
|---|---|---|---|
| magne.ai | 品牌与产品主站 | 了解产品、规格、安全和联系渠道 | 正式产品信息、官方素材 |
| w3.magne.ai | 应用与生态入口 | 了解 Agent 基础设施、活动、公开证据及供应量数据 | 活动状态、供应量/API、应用入口 |
| web3.magne.ai | MAGNE.AI Documentation & Disclosures | 阅读白皮书、开发接入、查证版本与规则 | 白皮书版本、技术文档、修订记录 |

网站职责是规划建议；目前 W3 实际还包含 AgentPay、AI BOX、Network、Build、Seasons、Trust、News 等入口。不要将它简化成纯活动页。

建议保留现有域名及可用 URL，在页面标题和跨站导航中明确写出 Brand / W3 / Docs，降低 W3 与 WEB3 名称相似造成的混淆。当前阶段不新增域名、不改变域名绑定。

## 2. 当前视觉审阅

本轮实际截图：1440×1000 桌面、390×844 手机。先记录初始 cookie 提示，再选择仅必要 cookies 后观察主要内容；没有登录、支付或链上交互。

1. 主站：纸色背景、黑色细线、红色强调、衬线大标题和编号构成鲜明的编辑式视觉。适合品牌叙事。手机首屏的长标题占比高；文档页不能直接沿用这种标题尺度。证据：main-clean.png、main-mobile-clean.png。
2. W3：近黑背景、青色强调、网格、等宽状态文字和终端演示建立技术识别。保留了 Preview / Sandbox / Testnet 等边界说明。部分灰色文案及小号状态文字可能增加阅读负担，实际对比度需在选定设计中测量，不能凭截图宣称达标。证据：w3-clean.png、w3-mobile-clean.png、w3-lower.png。
3. 当前白皮书试改：原深蓝框架、左侧站点菜单、完整目录和版本入口已具备基础；正文横向较宽、页内目录较长，手机上到正文需要经过较长的头部信息。建议收窄阅读栏、提供独立的章目录，不把每页都做成宣传首屏。证据：docs-desktop.png、docs-mobile.png。

本轮是视觉与信息架构抽样审阅，不是完整功能、性能或无障碍审计，也不把网站展示内容当作业务已实现的独立证明。

## 3. 推荐设计方向

推荐：浅色阅读页 + 深色技术组件。使用与主站协调的浅暖灰背景、深色正文、章节编号和细线；沿用 W3 的简洁状态标识。代码区、技术图和数据来源区可以用深色，正文不铺网格。

三个后续视觉候选，先用同一页和同一份内容比较：

| 候选 | 特点 | 取舍 |
|---|---|---|
| A：编辑式文档（推荐） | 浅色阅读背景、克制的标题、红色小面积强调、深色代码块 | 与主站亲近，适合白皮书与中英文长文 |
| B：技术文档 | 黑灰背景、青色链接、紧凑编号与状态 | 与 W3 接近，长表格与灰字需仔细处理 |
| C：中性资料库 | 中性白、石墨色、少量青色、规则化表格 | 最利于长文和打印，品牌戏剧性较弱 |

先制作三个 Tokenomics 桌面/手机视觉样稿，选择一个后再实施；此处的文字是方向说明，不冒充已经完成的视觉稿。随后以开发教程页验证代码、公式、表格等组件。不要一次重做全部页面。

拟定设计指标：正文桌面宽约 680–780px，中文约 32–42 字/行，正文16–18px、行高1.65–1.85；左侧站点树约240px，宽屏右侧章目录约200px，视实际内容测试调整。手机把章目录折叠为可访问控件；长表格自身滚动，并明确滚动提示。正式对比度按 WCAG AA 目标检测。

共同品牌元素：官方标志、统一产品名称、编号、细线、照片比例、状态标签语义。真实产品 PNG 保留透明背景和原比例；照片不强制裁成竖图。衬线仅用于有限标题，正文与中英混排采用易读字体，地址/哈希/代码采用等宽字体。减少无实际意义的动画。

## 4. 文档站信息架构

建议主入口：Overview / Whitepaper / Build / Network / Disclosures / Updates。

- Overview：文档读者入口、架构概览、术语、当前状态。
- Whitepaper：经济模型、分配与释放、治理、激励、版本选择。
- Build：网络配置、智能合约、应用、代币教程；明确测试环境。
- Network：L1/L2、RPC、Explorer、Faucet 对应关系。
- Disclosures：合约、储备、数据方法和带日期的执行披露；实时数字链接 W3 Supply，不手抄维护多份。
- Updates：发布公告、逐项差异、版本历史、勘误。

34个已采集独立页面逐一登记旧路径、新归属、内容负责人、处理状态。语义未变尽量保留旧路径；需要变更的建立单一跳转，保留原章节锚点或映射。不因为目录改名就让旧链接失效。

已知需核对的问题：get-mha 页实际显示 Layer2 说明；faucet 页实际显示 Gas/Fees；部分 L2 标签与 href 不一致；原白皮书保留的价格/上市表述与释放描述冲突。它们进入单独内容问题清单，由证据和负责人确认，不能在视觉改版中悄悄重写。

## 5. 白皮书与网站分别管理版本

建议并行管理三种记录：

| 记录 | 示例 | 变化触发 |
|---|---|---|
| 白皮书版本 | WP 1.1 | 规则、用途、机制或正式披露发生变更 |
| 网站发布 | Site release + Git commit | 布局、导航、组件、代码修复 |
| 数据快照 | BSC block + UTC timestamp | 新的链上观察，不自动改写历史白皮书 |

改颜色不会使白皮书升级；新增快照不覆盖旧快照；语言修正须记录但不制造不同语言的规则版本。

建议状态：Draft → In review → Approved → Published → Superseded。被替代版本仍可查阅。每个版本记录：文档ID、版本、状态、语言、变更类别、修改摘要、内容负责人、审阅人、批准记录、发布日期、生效日期、快照引用、上个版本、正文/PDF哈希、对应Git提交。

发布日期和生效日期分开；尚未批准时留空，不填虚构的日期或批准人。历史原文没有可靠发布日期/版本号时使用“修订前存档 · 捕获日期”，不要把今天分配的 v1.0 标签说成历史事实。

## 6. 这次 v1.1 的处理

保留当前试改和回退点。完整10,000,000,000 MHA总量、十项一级比例/数量、其余八类原文保持不变。将变更明确分为：

1. 规则修改：Exchange Campaigns 用途与释放条件；Market Makers 的 CEX/DEX 区分。
2. 执行披露：储备余额、交易所用途表、500 MHA测试路径。
3. 澄清：上市前空投、Season 1待执行奖励、Season 2未释放池的区别。

不得仅写“排版优化”或“文字说明”。历史转账的时间与新规则发布/生效时间分别披露；不能暗示新文字此前就已存在。项目负责人需确认这些规则修改的授权及适用范围；如涉及既有对外承诺，交由相关业务负责人和法律顾问审阅后确定处理，不用新版网页代替该项确认。

目前使用的 2026-09-28 17:56:21 UTC / BSC 124,568,474 是已保存的历史快照。发布时可保持这个明确标注的快照，或新增另一个已核验快照；不能把静态数值重标为实时数字。

版本页同时提供：简明变化摘要、按章节的新旧对照、未改变事项、适用范围/时间、数据依据、历史入口。原英文、中英文修订内容、数字表和公告做一致性核对；中文修订摘要不能标成完整中文版白皮书。

## 7. 内容与证据组织

建议逐步将可编辑 HTML 整理成 Markdown/MDX 正文 + 独立配置和数据，先迁移白皮书及一个开发教程，再迁移其余内容。当前 HTML 仍是保留的基线，转换前后比较正文、表格、代码和公式。

一级分配、交易所执行表采用共享结构化数据生成中英文网页/PDF/公告数字；规则说明仍按章节审阅，不靠自动翻译决定含义。每个数据集引用源文件或API快照、时间、区块、取值方法及性质（项目提供的用途分类 / 链上观察）。

发布包建议包含：冻结正文、对应 PDF、changelog、公告、数据快照、审批记录、校验结果和 Git tag。哈希是完整性校验，不代表监管或法律认证。

## 9. 验收及回退

- 内容：10项数量之和10,000,000,000，比例100%；本次执行表与快照一致；其他八类释放原文未被意外改动；中英数字同源。
- 阅读：桌面/平板/手机无整页溢出；表格可完整查阅；锚点与目录、版本选择、代码复制、数学公式正常；键盘焦点清晰。
- 路由：34页及栏目入口全部映射；原链接/锚点可达；无回到错误正式站的内部链接。
- 数据：静态快照与实时API分开；API失败显示不可用/最后更新时间，不伪造0或沿用旧值标为实时。
- 发布：未填写审批与生效信息的文档保持Draft；网站换皮不能自动把白皮书标为Published。
- 回退：设计改动独立提交，可恢复前一构建；已公开的白皮书若撤回或更正，保留该版本及撤回/更正记录，不静默删除披露历史。
